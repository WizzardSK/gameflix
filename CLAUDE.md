## How a click on the site starts a game

- A page link is `play:///<platform>/<list>/<rom>`. `webflix.sh` / `webflix.ps1`
  register the handler, and the handler fetches the launcher from the site
  (`https://wizzardsk.github.io/retroarch.sh`, `retroarch.ps1`).
- `generate.sh` builds the deployed `retroarch.sh` from three parts:
  - `retroarch.sh` from this repo (the header),
  - a `case` table generated from `platforms.csv`
    (`*"/platform/list/"*) core=...; ext=...; src=...;;`),
  - `retroarch.end` (all the logic).
- It also writes `launch.tsv` (read by the Windows launcher), and
  `gen_cores.py launch.tsv` writes `cores.json` (Android).
- Deploying without running all of `generate.sh`, which mounts archives:
  - Rebuild the deployed `retroarch.sh`: its tail is the previous
    `retroarch.end`. Swap it for the new one and check with `bash -n`.
  - After changing cores in `platforms.csv`, apply the same change to the core
    column of the deployed `retroarch.sh` and `launch.tsv`.
  - Then run `gen_cores.py launch.tsv > cores.json` and copy the result here
    too.
  - Copy `mame_deps.tsv` and `retroarch.ps1` to the site.
- `generate.sh` escapes `$` in list names inside the case patterns. Before that
  fix, `Demo [$B]` never matched.

## MAME (mame_libretro) – what the core needs

- Core 0.289 from the buildbot.
- Pass `-rompath "<rom dir>;~/share/bios;<system>/mame/bios;<system>/mame/roms"`.
  The core ignores `-rp`, so the BIOS was never found.
- The core's cmd parser knows only double quotes.
  - The launcher re-quotes the table's shell-style arguments.
  - A `"` is written as `\x22`: MAME posts `autoboot_command` through a Lua
    string, so Lua escapes apply.
  - Single quotes were being typed as text.
- The core prepends the content folder to any argument that follows a switch
  and contains a `.` without a `:`. So autoboot commands must not contain a
  dot: `*TAPE\nCHAIN""\n`, not `*T.\nCH.""`.
- TOSEC, No-Intro and Redump images: pass the full quoted path, and unzip
  first. MAME cannot load an image from inside a zip. A MAME set or softlist
  entry goes by its short name.
- System ROMs:
  - `mame_deps.tsv` lists per driver its own zip, the parent's, the BIOS chain,
    the ROM devices of the default config and those of plugged slot cards.
    Column 3 lists the driver's software lists.
  - It is generated by `gen_mame_deps.py mame0289.xml <deployed retroarch.sh>`.
    The input is `mame0289lx.zip` from the GitHub releases of mamedev/mame
    (`device_ref`, `slotoption devname`, device `romof`).
  - Regenerate it when the core's MAME version changes.
- ROM sources:
  - First choice is the recent non-merged set
    `mame-roms-non-merged-latest_202609`. Its members can be fetched singly and
    need no auth.
  - Fallback is `mame-merged`, which is MAME 0.268, older than the core.
  - `~/share/bios/.gameflix-recent` records the sets that came from the recent
    set, so old merged zips are fetched once more.
- Software lists: the XML always comes from libretro/mame master, for every
  list of the driver. Never use a system MAME's `hash/`, which is another
  version.
- CHD softlists (`mame-software-list-chds-2/<list>/<entry>/`):
  - The entry is a folder, so the launcher mirrors its `.chd` files.
  - If the CHD name differs from the list XML, the launcher links it under the
    expected name.
- Software named in core arguments is fetched into `~/share/bios/<list>/`.
  Examples: `famicom famibs30`, `m5_cart:basici`, `to7 -cart basic`,
  `pce -cart scdsys`.

## Firmware (Linux launcher)

- Sources, in order:
  1. buildbot system zips,
  2. the IA BIOS pack,
  3. MAME sets.
- `gameflix_mame_firmware` maps a file name to a MAME set and member, matched
  by CRC (libretro `System.dat` against the 0.289 listxml). It covers:
  - 3DO, ColecoVision (`coleco`), Odyssey 2 / Videopac+, Channel F,
  - FDS (`fc_disksys`), Kickstart 1.3 (`a500`), NDS (melonDS only),
  - BK monitors, 7800, `dc_boot`.
- No known source: Amiga 3.x/CD32 Kickstarts, BS-X (Satellaview/Sufami), Palm
  ROMs, BK BASIC10/FOCAL10, FreeDOS HDD CHDs.
- ROMs newer than every set: apple2gs `344s0047.bin`, lisa, smc777, pc9801.

## Other launcher behaviour

- With `ext`, the image is picked by type: the list's own extension first,
  then cue/gdi/m3u/ccd/chd/cdi/iso/bin/img, then the largest file.
  NonRedump lists mix types.
- A single-file `.7z` is passed on as that file. A multi-file one (Wii U NUS)
  is passed as its folder.
- A file that is not an archive is passed as it is (3DS `.cci`).
- J2ME runs on `squirreljme_libretro`, as the user decided.
  - freej2me has no Linux buildbot build.
  - SquirrelJME's libretro boot is still a `sjme_todo` stub (nanocoat
    `boot.c`), so it runs nothing yet.

## Open issues (from the per-list test, Sept 2026)

- About 35 lists are in formats MAME cannot load: Apple A2R/AIF/2MG
  (apple2ee), Astrocade PRG/WAV, SAM Coupé SAD, Colour Genie CGD, MZ-2000 MTW,
  GP32 FPK, 64DD NDD, FM Towns Redump `.7z`, parts of TRS-80.
  - `media_check.py` in the test harness lists them.
  - The user has not yet decided whether to hide them or find other cores.
- The TRS-80 Model 4 TOSEC lists are stale against `TOSEC-v2025-01-15`: the
  member names differ, so every download fails. The lists need regenerating.
- Some list entries need a different media switch per file (mixed TOSEC
  folders). Example: a disk image in a cassette list.
- Not verified here (headless test): black screens on Vectrex and Jaguar;
  PS2 (no GL context), Wii (core would not load), PSX CHD crash. Those crashes
  may just be the test environment.

## Testing the launcher

- A full test runs one game from every list on the site (1012 lists) through
  the real launcher and RetroArch, headless:
  - `HOME` is a temp dir holding `.config/rclone/rclone.conf`.
  - `retroarch` in `PATH` is a wrapper adding `--max-frames=1200
    --max-frames-ss`.
  - `mount-zip`, `ratarmount` and `umount` are stubs that extract into
    `~/iso`.
  - Runs use `dbus-run-session -- xvfb-run`.
- For each list, pick an entry with the list's most common extension and skip
  `[BIOS]` files. The first entry is often unrepresentative.
- Keep `HOME` short. Very long paths crash PUAE ("buffer overflow detected").
- Give each parallel worker its own `~/iso`. Sharing it produced false
  failures.
- Read MAME logs by "NOT FOUND (tried in …)". Ignore `OPTIONAL` and
  `NO GOOD DUMP KNOWN` lines.
- For autoboot lists, look at the screenshots. A black or empty screen after
  "RAN" can still mean a mistyped command.
